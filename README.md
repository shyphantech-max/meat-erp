# Zad ERP - Poultry & Mutton Supply (prototype)

Branded with the company logo (rooster & sheep in a green ring, `public/brand/`): logo green is the primary colour, sheep maroon the secondary.

A frontend-only, fully interactive ERP prototype for a Saudi company that imports, buys and
distributes chicken and mutton to B2B customers (restaurants, hotels, supermarkets, wholesalers,
caterers). It digitises the paper flow end to end:

**Local purchase / import → GRN → warehouse inventory → driver van loading → B2B delivery / van
sales → payment collection → stock returns → daily driver settlement → owner dashboard**

## Run

```bash
npm install
npm run dev        # http://localhost:5240
npm run build      # type-check + production build
npx vite-node scripts/check-seed.ts    # print demo-data counts
npx vite-node scripts/check-logic.ts   # transaction invariant tests (no double counting etc.)
```

No backend, login server or paid APIs. All data lives in the browser's LocalStorage; use
**Profile → Reset demo data** (or Settings) to regenerate it. An untouched demo opened on a later
day regenerates itself, so “today” always has activity.

## How it fits together

| Path | What it holds |
| --- | --- |
| `src/types.ts` | Domain model (products, batches, POs, GRNs, invoices, payments, van ledger, settlements…) |
| `src/store/logic.ts` | Every business transaction (create PO, approve GRN, load van, complete delivery, record payment, submit/approve settlement…) with status guards |
| `src/store/derive.ts` | Pure calculations: invoice balance, outstanding, ageing, FEFO stock, van stock, settlement reconciliation |
| `src/store/useStore.ts` | Persisted store; `run()` executes a transaction on an Immer draft and commits only on success |
| `src/data/seed.ts` | Demo data generated by *replaying* the business through `logic.ts`, so it is internally consistent |
| `src/components/common` | Page header, KPI cards, status badges, line-item editor, print dialog, confirm dialog… |
| `src/components/docs` | Printable tax invoice, payment receipt, loading slip, settlement report |
| `src/modules/*` | One folder per sidebar module + `driver-app` (mobile driver interface at `/driver`) |
| `src/i18n` | English keys → Arabic dictionaries; Arabic switches the layout to RTL |

### Integrity rules

* GRN approval posts stock once; re-approval is refused.
* Van stock is a ledger (`vanMovements`): loads add, deliveries / van sales / returns / losses subtract, so
  *Opening + Loaded + Customer returns - Delivered/Sold - Returned - Loss = Closing* always holds. Nothing can go
  negative.
* Stock leaves warehouses first-expiry-first-out; expired batches are never picked.
* Payments are allocated to invoices; overpayment, reused bank references, repeated idempotency keys and
  same-amount repeats within two minutes are rejected.
* Settlements follow *Submitted → Under review → Verified → Approved → Closed*; a driver day can be settled
  once, and closing a day blocks further loading or sales for it.

## Demo data

10 suppliers (6 international, 4 local) · 20 B2B customers + a walk-in (counter) account · 15 chicken & mutton products · 3 warehouses
(Riyadh, Jeddah, Dammam) · 8 drivers · 8 reefer vehicles · 30 purchase orders · 11 import shipments · 25 GRNs ·
53 sales invoices (incl. 3 counter sales) · 40 deliveries · 38 payment collections · 8 daily settlements, plus 12 months of
register-archive totals for the trend chart. Company and partner names are fictional.

VAT is configurable (default 15%). Printed invoices are demo documents; the prototype does **not** claim ZATCA
e-invoicing compliance.
